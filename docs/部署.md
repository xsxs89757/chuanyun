# 部署服务端

[English](deploy.md) · [中文](部署.md)

一次性的事，做完之后同事装上客户端就能用。

## 你需要准备

- 一台有公网 IP 的 Linux 服务器（现有的就行，不用新开；目前预编译包只有 x86_64）
- 一个**已备案**的域名，能加一条泛解析记录
- 该域名的泛域名证书（微信回调要求 HTTPS）

关于备案：微信公众号、小程序、支付的回调地址都要求备案域名。如果你的域名已经在用了，那就已经满足。

先想好给隧道用哪个子域，比如 `t.example.com`。**建议用独立子域而不是主域**：隧道地址和生产站点分开，出问题不互相牵连，Cookie 也不会串。

## 一条命令装完

```bash
curl -fsSL https://github.com/xsxs89757/chuanyun/releases/latest/download/install-server.sh \
  | sudo sh -s -- --domain t.example.com
```

脚本会做这些：下载最新版并核对校验和 → 装到 `/usr/local/bin` → 建 `chuanyun` 系统用户 →
写一份 `/etc/chuanyun/server.toml` → 注册 systemd 服务并启动 → 把接下来要做的四步打在屏幕上。

不放心把脚本管道进 root shell 的话，先读一遍——就一个文件，
[`scripts/install-server.sh`](../scripts/install-server.sh)，也可以照下面的[手动安装](#手动安装)来。

其他选项：

```bash
--version v0.1.0      # 装指定版本，默认最新
--control-port 7100   # 控制通道，客户端连它（默认 7000）
--http-port 7080      # HTTP 入口，只听回环，给 nginx 反代（默认 7080）
--admin-port 7101     # 管理接口，只听回环（默认 7001）
--no-start            # 装完不启动
--uninstall           # 卸载（数据目录会留着）
```

**端口多半要改。** 服务器上跑着别的东西是常态——frp 默认就占 7000，
docker 常占 7001。脚本会在动手之前先查这三个端口，被占就直接告诉你是哪个、
被谁占着、该加哪个参数，并且什么都不动。

## GitHub 下不动的话

国内服务器上 `raw.githubusercontent.com` 基本连不上，`github.com` 也时通时不通
（实测某台机器上下载速度只有 20KB/s 左右）。所以：

- 上面那条命令用的是 `github.com/…/releases/latest/download/…`，它会跳到
  `objects.githubusercontent.com`——那个通得多。**不要**换成 raw 那条地址。
- 脚本自带 3 次重试，下载给了 600 秒预算。

实在下不来就离线装：在能上 GitHub 的机器上下好，传过去，用内网镜像模式装。

```bash
# 在能上网的机器上（比如你自己的电脑）
VER=0.1.0
curl -fLO https://github.com/xsxs89757/chuanyun/releases/download/v$VER/chuanyun-server-$VER-linux-x86_64.tar.gz
curl -fLO https://github.com/xsxs89757/chuanyun/releases/download/v$VER/SHA256SUMS
curl -fLO https://github.com/xsxs89757/chuanyun/releases/download/v$VER/install-server.sh
scp chuanyun-server-$VER-linux-x86_64.tar.gz SHA256SUMS install-server.sh root@服务器:/tmp/

# 在服务器上
cd /tmp && CHUANYUN_BASE_URL=file:///tmp sh install-server.sh \
  --domain t.example.com --version v$VER
```

`CHUANYUN_BASE_URL` 指向任何放着这两个文件的地方都行——本地目录、公司内网的
HTTP 服务、对象存储。校验和照常核对。

## 装完之后还差四步

脚本已经把这四步连同你的实际 IP、端口、证书指纹一起打在屏幕上了。这里是同一份，方便回头查。

### 1. 域名解析

```
*.t.example.com   A   你的服务器公网IP
```

### 2. 放行控制通道端口

客户端出站连这个端口（默认 7000），这条连接自带 TLS，**不经过 nginx**。

```bash
sudo ufw allow 7000/tcp
# 或者：sudo firewall-cmd --add-port=7000/tcp --permanent && sudo firewall-cmd --reload
```

⚠️ **云服务器还要去控制台的安全组里同样放行。**只开 ufw 不够，这是最常见的「装完连不上」原因。

### 3. nginx 反代

服务端只监听内网明文 HTTP（`127.0.0.1:7080`），443 和证书仍然归 nginx 管——不用抢端口，证书续期也沿用你现在的流程。

样例配置装完就在 `/etc/chuanyun/nginx.conf.example`（仓库里也有一份：[`deploy/nginx.conf.example`](../deploy/nginx.conf.example)）。改掉域名和证书路径就能用。四个要点：

| 配置 | 为什么 |
|---|---|
| `proxy_set_header Host $host` | 子域名路由完全靠原始 Host，不透传就找不到隧道 |
| `Upgrade` / `Connection` 头 | WebSocket 要用 |
| `proxy_buffering off` | 否则 SSE 不实时、大响应会先落盘 |
| `client_max_body_size 200m` | 大文件上传 |

**宝塔面板**：把配置放进 `/www/server/panel/vhost/nginx/` 下的独立 conf，别直接改面板生成的站点配置——面板重写时会覆盖掉。

### 和已有的 frp 共存

很多人这台服务器上已经跑着 frp。两者可以并存，关键是**给穿云单独一层子域**。

假设 frp 的 `subDomainHost = example.com`（也就是它占着 `xxx.example.com`），
那就把穿云的 `domain_suffix` 设成 `t.example.com`，然后单独写一个 server 块：

```nginx
server {
    listen 443 ssl;
    server_name *.t.example.com;      # 比 *.example.com 更长，nginx 优先匹配它
    ssl_certificate     /path/to/t.example.com/fullchain.pem;
    ssl_certificate_key /path/to/t.example.com/privkey.pem;
    location / { proxy_pass http://127.0.0.1:7080; /* 其余头同上 */ }
}
```

nginx 的前缀通配符按**最长优先**匹配，所以 `*.t.example.com` 会赢过 frp 那条
`*.example.com`，只有这一层走到穿云，其余照旧交给 frp，互不干扰。

两件事要注意：

- **端口**。frp 默认占 7000，正好是穿云控制通道的默认端口。安装时用
  `--control-port` 换一个（安装脚本会先查，撞了直接告诉你）。
- **证书**。`*.example.com` 的证书**盖不住** `xxx.t.example.com`——泛域名证书只覆盖
  一级。要单独给 `*.t.example.com` 签一张，泛域名只能走 DNS-01：宝塔「SSL → 申请证书」
  里选 DNS 验证即可，或者用 acme.sh：

  ```bash
  acme.sh --issue --dns dns_ali -d '*.t.example.com' -d 't.example.com' --server letsencrypt
  acme.sh --install-cert -d '*.t.example.com' --ecc \
      --fullchain-file /path/to/t.example.com/fullchain.pem \
      --key-file       /path/to/t.example.com/privkey.pem \
      --reloadcmd      "nginx -t && nginx -s reload"
  ```

### 4. 发凭证

```bash
sudo chuanyun-server user add zhangsan
```

输出的凭证**只显示这一次**——库里只存哈希。丢了就重发一张：

```bash
sudo chuanyun-server user reissue zhangsan
```

原来那张立刻失效，对方的在线连接也会断开，用新凭证重新登录即可。
（`user add` 撞到已有名字会直接报错，不会覆盖——免得手一抖把正在用的人踢下线。）

把它连同**证书指纹**一起发给本人：

```bash
chuanyun-server fingerprint
```

指纹是客户端用来确认「连的确实是这台服务器」的。它不是秘密，可以和凭证走同一个渠道发。

## 验证

让同事装上客户端、输入凭证、开一条隧道，然后从外网访问那个地址。

顺利的话就到此为止了。不顺利的话看[排查](#排查)。

## 日常管理

发凭证、升级、证书、排查这些日常操作单独整理在[运维速查](运维.md)，这里只列最常用的：


```bash
chuanyun-server status                # 现在几个人在线、几条隧道
chuanyun-server user list             # 谁有凭证、有没有过期
chuanyun-server user add <名字>       # 再发一个人
chuanyun-server user reissue <名字>   # 换一张凭证（丢了、或吊销后要恢复）
chuanyun-server user revoke <名字>    # 吊销（在线连接会立刻断开）
chuanyun-server kick <名字>           # 只踢下线，凭证还有效
chuanyun-server fingerprint           # 再看一次证书指纹
chuanyun-server domain add <用户> <域名>   # 登记一个自定义域名

systemctl status chuanyun-server      # 服务在不在跑
journalctl -u chuanyun-server -f      # 看日志
```

## 升级

重新跑一遍安装命令就行，配置和数据都不动：

```bash
curl -fsSL https://github.com/xsxs89757/chuanyun/releases/latest/download/install-server.sh | sudo sh
```

升级不用带 `--domain`（配置已经在了）。服务重启期间隧道会瞬断几秒，客户端自己会重连回来，地址不变。

## 卸载

```bash
curl -fsSL https://github.com/xsxs89757/chuanyun/releases/latest/download/install-server.sh | sudo sh -s -- --uninstall
```

会停掉并移除服务、删掉二进制。**配置和数据故意留着**——里面有自签证书，删了之后所有客户端的指纹都得重配。确认不要了再手动删：

```bash
sudo rm -rf /etc/chuanyun /var/lib/chuanyun && sudo userdel chuanyun
```

## 手动安装

不想用脚本，或者机器上没有 systemd：

```bash
# 1. 下载解压（版本号换成你要的）
VER=0.1.0
curl -fLO https://github.com/xsxs89757/chuanyun/releases/download/v$VER/chuanyun-server-$VER-linux-x86_64.tar.gz
curl -fLO https://github.com/xsxs89757/chuanyun/releases/download/v$VER/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar xzf chuanyun-server-$VER-linux-x86_64.tar.gz

# 2. 装二进制
sudo install -m 0755 chuanyun-server /usr/local/bin/

# 3. 配置
sudo mkdir -p /etc/chuanyun
sudo tee /etc/chuanyun/server.toml > /dev/null <<'TOML'
[http]
domain_suffix = "t.example.com"

[storage]
data_dir = "/var/lib/chuanyun"
TOML

# 4. 系统用户与数据目录
sudo useradd --system --no-create-home --shell /usr/sbin/nologin chuanyun
sudo mkdir -p /var/lib/chuanyun
sudo chown chuanyun /var/lib/chuanyun
sudo chmod 0700 /var/lib/chuanyun

# 5. systemd
sudo install -m 0644 chuanyun-server.service /etc/systemd/system/
sudo systemctl enable --now chuanyun-server
```

配置只有 `domain_suffix` 是必填的，其余都有合理默认值：控制通道 `0.0.0.0:7000`、HTTP 入口 `127.0.0.1:7080`、管理接口 `127.0.0.1:7001`。

建议再加一行 `[control] public_addr`——**客户端要填的地址**。`listen` 是绑定地址
（`0.0.0.0:7000` 谁都连不上），服务端也猜不到自己的公网名字，所以要单独写一份，
下载页才能把它显示给同事：

```toml
[control]
public_addr = "tunnel.example.com:7000"   # 或者 "1.2.3.4:7000"
```

一键安装脚本会自动探测公网 IP 填好这一项。

没有 systemd 的话直接跑：`chuanyun-server -c /etc/chuanyun/server.toml run`。

然后回到[装完之后的四步](#装完之后还差四步)。

## 排查

**客户端连不上**

按这个顺序查：

```bash
nc -vz 你的服务器 7000            # 端口通不通
systemctl status chuanyun-server   # 服务在不在跑
chuanyun-server fingerprint        # 指纹和客户端里填的是不是同一个
```

九成是**云安全组没放行 7000**——`ufw allow` 只管系统防火墙，云厂商控制台那层是独立的。

指纹填错的话客户端会明确提示「证书指纹不符」，不会含糊过去。

**隧道地址打开是 404 品牌页**

请求到了服务端，但没找到对应的隧道。两种可能：客户端那边隧道没开着；或者 nginx 没透传 Host 头（`proxy_set_header Host $host`）——子域名路由完全靠它。

**隧道地址打不开 / 证书报错**

```bash
dig zhangsan-test.t.example.com   # 泛解析生效了吗
```

再确认泛域名证书确实覆盖了这一级子域（`*.t.example.com` 的证书不覆盖 `a.b.t.example.com`）。

**微信提示回调地址不合法**

微信填的是具体子域名，不接受通配符。把客户端里显示的完整地址原样贴进去。域名必须已备案。

**老安卓或微信内打不开，浏览器却正常**

多半是证书链的问题。Let's Encrypt 新根在部分老设备上不被信任，签发时选完整链，或者换一家的免费证书。

**服务起不来**

```bash
journalctl -u chuanyun-server -n 30 --no-pager
```

配置写错的话它会直接说是哪个键。打错的键名不会被默默忽略——这是故意的，宁可启动就报错。

## 给同事的下载页

服务端带一个下载页。把安装包放进下载目录，页面上就会出现对应的按钮：

```bash
sudo mkdir -p /var/lib/chuanyun/downloads
sudo cp chuanyun-*.dmg chuanyun-*.msi /var/lib/chuanyun/downloads/
sudo chown -R chuanyun /var/lib/chuanyun/downloads
```

只认 `.dmg` / `.msi` / `.exe`，目录里的其他文件既不会列出来也下载不到。

**这个目录同时也是升级提示的依据**：服务端每次心跳看一眼这里最新的包是哪个版本，
比客户端新就提示「有新版本」——已经连着的客户端十几秒内就能看到。所以发新版只要把包
丢进来，旧的删掉。

想换目录、或者让提示里带上下载链接，在配置里加：

```toml
[admin]
download_dir = "/opt/chuanyun/pkgs"
download_url = "https://t.example.com/download"   # 横幅上「去下载」指向这里
```

页面在管理接口上（默认 `127.0.0.1:7001`）。**反代时只放行下载相关的两条路径**——
其余管理接口能踢人、能列用户和审计日志，不要暴露：

```nginx
# 装包页面与安装包本身
location ^~ /chuanyun/download { proxy_pass http://127.0.0.1:7001/download; }
# 客户端查更新（可选）
location =  /chuanyun/version  { proxy_pass http://127.0.0.1:7001/api/client/version; }
```

`^~` 是必须的：安装包走的是 `/chuanyun/download/<文件名>`。

页面上已经写好了「第一次打开怎么绕过系统拦截」这类说明，也会显示域名后缀和证书指纹，
同事照着填就行。
