# 怎么用

## 装好之后

打开穿云，输入管理员发给你的凭证，点登录。

如果装的是公司内部版，服务器地址和证书指纹已经在里面了，你只需要填凭证。

**第一次打开被系统拦住**：这个应用没有购买代码签名证书（一年几百刀，内部工具不值当）。

- macOS：右键点图标 → 打开 → 再点「打开」。直接双击会被拦。
- Windows：SmartScreen 提示时点「更多信息」→「仍要运行」。

每台机器做一次就好。

## 开一条隧道

假设你本地跑着一个服务，端口 8082。

点「新建隧道」，名字填 `wx`，端口填 `8082`。几秒后你会拿到：

```
https://你的名字-wx.t.公司域名
```

这个地址**固定不变**，重启客户端、重启电脑都是它。可以放心填进微信后台。

外面访问这个地址，请求就会到你本机的 8082。

## 调微信回调

1. 本地把服务跑起来
2. 开一条隧道指向它
3. 把隧道地址填进微信后台的回调 URL
4. 打断点，触发回调

回调直接打到你本机，可以单步调试。地址固定，明天再来不用重新填。

## 项目怎么接

### 一次性的：界面上建

适合个人的、临时的隧道。

### 团队项目：写进配置文件

在项目根目录放一个 `chuanyun.toml`，提交到 git，团队共享：

```toml
project = "crm"

[[tunnels]]
name = "api"
port = 8082

[[tunnels]]
name = "admin"
port = 5173
```

以后加端口就是加几行，同事拉下来重新导入即可。

### 脚本自动接入

穿云在本机 `127.0.0.1:7075` 提供了 HTTP 接口。启动脚本里加一行，端口就自动接上了：

```bash
curl -s -X POST localhost:7075/api/tunnels \
     -d '[{"port":8082,"name":"api"},{"port":5666,"name":"web"}]'
```

按名字幂等——脚本重复跑不会开出一堆重复隧道。

### 让回调地址跟着环境走

这是最省心的用法。业务代码里别写死地址，问穿云要：

```bash
# 隧道开着 → 公网地址；没开 → http://127.0.0.1:8082
curl -s 'localhost:7075/api/resolve?port=8082&plain=1'
```

放进环境变量，业务代码一个字都不用改：

```bash
export WX_CALLBACK_BASE=$(curl -s 'localhost:7075/api/resolve?port=8082&plain=1')
npm run dev
```

穿云没开着的时候这条命令会失败，脚本里可以兜一下：

```bash
BASE=$(curl -sf 'localhost:7075/api/resolve?port=8082&plain=1' || echo "http://127.0.0.1:8082")
```

## 本地接口一览

| 接口 | 作用 |
|---|---|
| `GET /api/status` | 连上没有、域名后缀是什么 |
| `GET /api/tunnels` | 当前所有隧道 |
| `POST /api/tunnels` | 注册隧道，接受单个对象或数组 |
| `DELETE /api/tunnels/{名字}` | 注销 |
| `GET /api/resolve?port=N` | 这个端口现在对外的地址，加 `&plain=1` 返回纯文本 |
| `GET /api/requests` | 穿过隧道的请求记录，加 `?tunnel=名字` 只看一条隧道 |
| `GET /api/requests/{id}` | 某条请求的完整内容 |
| `POST /api/requests/{id}/replay` | 重放这条请求 |
| `DELETE /api/requests` | 清空记录 |
| `GET /api/connects` | 当前的接入 |
| `POST /api/connects` | 新建接入：`{"local_port":8082,"from":"zhangsan-api"}` |
| `DELETE /api/connects/{端口}` | 移除接入 |

只监听回环，并且会拒绝浏览器发来的请求（防的是恶意网页偷偷访问你的本地服务）。所以这些接口只能从命令行和脚本调，不能在网页里 fetch。

## 给隧道加个口令

演示给客户看、或者隧道要开一整天的时候，加一道门比较安心：

在隧道设置里填 `用户名:口令`，访问时浏览器会弹出输入框。没填对的请求根本到不了你的本地服务。

## 连数据库、SSH（TCP 隧道）

HTTP 之外的东西走 TCP 隧道：新建时选 TCP，穿云会分配一个公网端口。

```
127.0.0.1:3306  →  server.example.com:20017
```

拿这个地址当数据库主机名连就行。注意 TCP 隧道一条占一个公网端口，池子有限，用完记得关。

## 看请求、重放请求

「请求」页里能看到穿过隧道的每一个请求：方法、路径、状态码、耗时。

真正有用的是**重放**——支付回调只会推送有限几次，推完就没了。点一下重放，同一份报文（同样的签名、同样的时间戳）再打一次，想调几次调几次。

记录只存在你自己的电脑内存里，关掉应用就没了。Cookie 和 Authorization 这类头会自动隐去，截图发群里也不至于泄露。

## 用同事的服务（接入）

前端调试时不想在本机跑一整套后端，想直接用同事那份（连着他的测试数据）：

「接入」页里填来源（比如 `zhangsan-api`）和要映射到的本地端口（比如 `8082`），你本机的 `127.0.0.1:8082` 就通向张三的服务了。

**好处是你的配置不用改**：前端 proxy、`.env`、代码里照常写 `127.0.0.1:8082`，「连自己的 / 连张三的」只是开关这条接入的区别。

如果你自己也把服务跑在 8082 上，接入会告诉你端口被占——停掉自己那个，或者换个端口。

## Vite 项目一行接入

```bash
npm i -D vite-plugin-chuanyun     # pnpm add -D / yarn add -D 都行
```

```ts
import chuanyun from 'vite-plugin-chuanyun'
export default defineConfig({ plugins: [chuanyun({ name: 'admin' })] })
```

dev server 起来就自动建好隧道，地址打印在 Local 旁边。它顺带解决了两件烦人事：Vite 默认会拦下隧道域名（`Blocked request`），以及 5173 被占时端口会漂。

详见[插件说明](../integrations/vite-plugin-chuanyun/README.md)。

## 常见问题

**地址打开显示「没有正在运行的隧道」**

隧道没开着，或者地址拼错了。看一眼客户端里那条隧道的开关。

**隧道开着，但访问报「隧道那头没有响应」**

本地服务没起来，或者端口填错了。客户端会在那条隧道下面显示具体原因。

**前端 dev server 说 "Blocked request: this host is not allowed"**

Vite 默认只允许 localhost 访问。装上[插件](../integrations/vite-plugin-chuanyun/README.md)会自动处理，
或者手动在 `vite.config.ts` 里放行：

```ts
server: { allowedHosts: ['.t.公司域名'] }
```

**电脑合盖再打开，隧道还在吗**

在。客户端会自己重连，隧道也会自动恢复，地址不变。

**关掉窗口是不是就断了**

不是。关窗口只是收进托盘，隧道继续开着。真要退出走托盘菜单里的「退出」。

**配置文件在哪**

```bash
chuanyun --print-state-path
```

## 注意

隧道地址是**公网可达**的。开着的时候，任何知道地址的人都能访问到你本机的那个端口。

- 别把连着生产数据库的服务开出去
- 演示完随手关掉
- 不确定的时候，关掉比开着好
