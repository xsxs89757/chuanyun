# 发版

三样东西各有各的节奏，互不打扰。

## 客户端与服务端

打 tag 就行，CI 会在三个平台上构建并自动创建 GitHub Release：

```bash
git tag v0.1.0
git push origin v0.1.0
```

产出：

| 产物 | 说明 |
|---|---|
| `chuanyun-server-linux-x86_64.tar.gz` | 服务端静态二进制 + systemd 单元 + nginx 样例 |
| `穿云-0.1.0.dmg` | macOS 客户端（Intel + Apple Silicon 通用包） |
| `*.msi` | Windows 客户端 |

发版前把 `Cargo.toml` 里的 `version` 改好，tag 要和它对上。

### 客户端怎么知道有新版

客户端在设置页点「检查更新」时，会去查 **GitHub Releases**——CI 已经把安装包
传到那里了，不需要再单独维护一份版本清单。

内部部署如果不想让客户端连外网，把品牌配置里的 `update_url` 指向自己的服务端：

```toml
# brand/company.toml
update_url = "https://tunnel.example.com/chuanyun/api/client/version"
```

服务端的管理接口已经提供了这个返回，形状客户端认识。

只提示、不自动安装——安装包没有代码签名，静默替换一个未签名的二进制不是好主意。

## Vite 插件

插件的版本和主程序无关，所以用自己的 tag 前缀：

```bash
# 1. 改版本号
cd integrations/vite-plugin-chuanyun
npm version patch          # 或 minor / major

# 2. 打 tag 推上去
git add -A && git commit -m "插件 v0.1.1"
git tag plugin-v0.1.1
git push origin main --tags
```

CI 会跑测试、核对 tag 与 `package.json` 的版本是否一致，然后 `npm publish`。

### 一次性准备：npm 令牌

**这一步需要你自己做**，我没法替你操作：

1. 到 [npmjs.com](https://www.npmjs.com/) 注册（或登录）一个账号
2. 头像 → Access Tokens → Generate New Token → **Granular Access Token**
   - Packages and scopes：选 `Read and write`
   - 有效期按需要设，建议一年
3. 复制生成的令牌
4. 到仓库的 Settings → Secrets and variables → Actions → New repository secret
   - Name：`NPM_TOKEN`
   - Secret：粘贴刚才的令牌

配好之后，以后每次打 `plugin-v*` 的 tag 就会自动发布。

也可以在本地手动发一次：

```bash
cd integrations/vite-plugin-chuanyun
npm login
npm publish --access public
```

### 不想发 npm 也能用

包名 `vite-plugin-chuanyun` 目前没被占用，但如果你暂时不想发，
使用方有两条路（[插件说明](../integrations/vite-plugin-chuanyun/README.md)里也写了）：

**pnpm 直接从仓库子目录装**：

```bash
pnpm add -D "github:xsxs89757/chuanyun#path:/integrations/vite-plugin-chuanyun"
```

npm 和 yarn 不支持子目录，所以走 tarball：

```bash
cd chuanyun/integrations/vite-plugin-chuanyun
npm install && npm pack
# 把生成的 .tgz 发给同事，或者放公司内网
npm i -D /path/to/vite-plugin-chuanyun-0.1.0.tgz
```

`package.json` 里配了 `prepare` 脚本，所以从 git 装的时候会自己构建
（`dist/` 没有进仓库）。
