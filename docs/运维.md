# 运维速查

[English](operations.md) · [中文](运维.md)

部署完之后日常要敲的命令都在这儿。第一次部署看[部署服务端](部署.md)。

下面用这几个占位符，换成你自己的：

| 占位符 | 例子 |
|---|---|
| `<服务器>` | `1.2.3.4` 或 `tunnel.example.com` |
| `<后缀>` | `t.example.com` |
| `<控制端口>` | `7000`（frp 占了就换，比如 `7100`） |

## 发凭证

```bash
chuanyun-server user add 张三
```

凭证**只显示这一次**——库里只存哈希。把它连同证书指纹一起发给本人：

```bash
chuanyun-server fingerprint
```

指纹不是秘密，可以和凭证走同一个渠道。

**凭证丢了**（或者误吊销要恢复）：

```bash
chuanyun-server user reissue 张三
```

旧的立刻失效，在线连接也会断开，对方用新凭证重新登录即可。
`user add` 撞到已有名字会直接报错、不覆盖——免得手一抖把正在用的人踢下线。

**离职 / 停用**：

```bash
chuanyun-server user revoke 张三    # 吊销，在线连接立刻断
chuanyun-server kick 张三            # 只踢下线，凭证还有效
```

## 看状态

```bash
chuanyun-server status                  # 几个人在线、几条隧道
chuanyun-server user list               # 谁有凭证、过没过期
systemctl status chuanyun-server        # 服务在不在跑
journalctl -u chuanyun-server -f        # 实时日志
journalctl -u chuanyun-server -n 50 --no-pager   # 最近 50 行
```

管理接口只监听回环，所以只能在服务器上调。它返回 JSON，适合接监控：

```bash
curl -s localhost:<管理端口>/status    # 同 chuanyun-server status
curl -s localhost:<管理端口>/tunnels   # 当前所有隧道
curl -s localhost:<管理端口>/users     # 用户及在线状态
curl -s localhost:<管理端口>/audit     # 审计记录
```

> 这几个接口会拒绝带浏览器特征头的请求（`Origin` / `Sec-Fetch-Site`），
> 也要求 `Host` 是回环地址——防的是恶意网页偷偷访问服务器的本地端口。
> 所以别指望在浏览器里打开它们，用 curl。

## 升级

重跑一遍安装命令就是升级，配置和数据都不动：

```bash
curl -fsSL https://github.com/xsxs89757/chuanyun/releases/latest/download/install-server.sh | sudo sh
```

服务重启期间隧道瞬断几秒，客户端自己会重连，地址不变。

**国内服务器下载慢或连不上 GitHub**（很常见）就离线装——在能上网的机器上下好传过去：

```bash
# 本地
VER=0.1.4
B=https://github.com/xsxs89757/chuanyun/releases/download/v$VER
for f in chuanyun-server-$VER-linux-x86_64.tar.gz SHA256SUMS install-server.sh; do
    curl -fLO $B/$f
done
scp chuanyun-server-$VER-linux-x86_64.tar.gz SHA256SUMS install-server.sh root@<服务器>:/tmp/

# 服务器上
cd /tmp && CHUANYUN_BASE_URL=file:///tmp sh install-server.sh --version v$VER
```

`CHUANYUN_BASE_URL` 指向任何放着这些文件的地方都行——本地目录、内网 HTTP、对象存储。校验和照常核对。

**回滚**到某个版本，加 `--version`：

```bash
sudo sh install-server.sh --version v0.1.3
```

## 改配置

配置在 `/etc/chuanyun/server.toml`，改完重启：

```bash
sudo systemctl restart chuanyun-server
```

打错的键不会被默默忽略——启动就报错，`journalctl` 里会指名道姓说是哪个键。

常改的几项：

```toml
[control]
listen = "0.0.0.0:<控制端口>"        # 绑定地址
public_addr = "<服务器>:<控制端口>"  # 客户端该填的地址，下载页显示它

[http]
domain_suffix = "<后缀>"

[admin]
download_dir = "/var/lib/chuanyun/downloads"

[limits]
max_tunnels_per_user = 10
```

**升级不会动已有配置**，所以新版本加的配置项要自己补上去。

## 下载页

把安装包丢进下载目录，页面上就会出现按钮：

```bash
sudo cp chuanyun-*.dmg chuanyun-*.msi /var/lib/chuanyun/downloads/
sudo chown -R chuanyun:chuanyun /var/lib/chuanyun/downloads
```

只认 `.dmg` / `.msi` / `.exe`，目录里其他文件既不列出也下载不到。发新版时把旧包删掉：

```bash
sudo rm -f /var/lib/chuanyun/downloads/*0.1.3*
```

## nginx

穿云的 nginx 配置是**手写的**，不是宝塔面板生成的——面板站点列表里看不到它。

```bash
# 宝塔的话在这儿
ls /www/server/panel/vhost/nginx/<后缀>.conf

nginx -t && nginx -s reload    # 一定先 -t 再 reload
```

改之前先备份：`cp <文件> <文件>.bak`。语法错了 `nginx -t` 会拦下，
但**别在没跑 `-t` 的情况下 reload**——那会把整台机器上所有站点一起带下去。

## 证书

泛域名证书只能走 DNS-01。acme.sh 装好后会自己续期（每天 4 次检查，到期前自动换），
钩子里带了 reload，不用管。

```bash
/root/.acme.sh/acme.sh --list                    # 有哪些证书、什么时候续
/root/.acme.sh/acme.sh --cron --home /root/.acme.sh   # 手动跑一次续期检查
```

证书快到期但没自动续（比如 DNS 密钥换了），先看日志再手动强制续：

```bash
/root/.acme.sh/acme.sh --renew -d '*.<后缀>' --ecc --force
```

看证书覆盖哪些域名、什么时候到期：

```bash
openssl x509 -in /path/to/fullchain.pem -noout -ext subjectAltName -dates
```

> **泛域名证书只覆盖一级子域。** `*.example.com` 的证书对 `a.b.example.com`
> **无效**。给隧道单独用一层子域时，要单独签一张 `*.<后缀>`。

## 排查

**客户端连不上**

按这个顺序查：

```bash
nc -vz <服务器> <控制端口>       # 端口通不通（从客户端那台机器上跑）
systemctl status chuanyun-server  # 服务在不在跑
chuanyun-server fingerprint       # 指纹和客户端填的是不是同一个
```

九成是**云安全组没放行控制端口**——`ufw allow` 只管系统防火墙，云厂商控制台那层是独立的。

**隧道地址打开是 404 品牌页**

请求到了服务端但没找到隧道。要么客户端那边隧道没开着，要么 nginx 没透传 Host
（`proxy_set_header Host $http_host`）——子域名路由完全靠它。

**服务起不来**

```bash
journalctl -u chuanyun-server -n 30 --no-pager
```

最常见的是端口被占（`Address already in use`）。查是谁占的：

```bash
ss -tlnp | grep -E ':(7000|7080|7001) '
```

**别只看 `systemctl is-active`。** `Type=simple` 的服务一 fork 出来就报 active，
配上 `Restart=always`，一个起来就崩的服务会在 active / failed / activating
之间反复循环，`is-active` 正好可能撞上某个瞬间的 active。以这个为准：

```bash
chuanyun-server status    # 能应答才是真起来了
```

**看谁在什么时候做了什么**

```bash
curl -s localhost:<管理端口>/audit | python3 -m json.tool
```

## 卸载

```bash
curl -fsSL https://github.com/xsxs89757/chuanyun/releases/latest/download/install-server.sh \
  | sudo sh -s -- --uninstall
```

停服务、删二进制，**配置和数据故意留着**——数据目录里有自签证书，删了之后所有客户端的指纹都得重配。确认不要了再手动删：

```bash
sudo rm -rf /etc/chuanyun /var/lib/chuanyun && sudo userdel chuanyun
```

nginx 配置和证书要单独清。
